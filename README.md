# Морской бой по локальной сети

![Python](https://img.shields.io/badge/python-3.12-3776AB?logo=python&logoColor=white)
![License](https://img.shields.io/badge/license-MIT-green)

Классический «Морской бой» для двух ноутбуков в одной сети. Один игрок создаёт игру,
второй находит её автоматически, IP-адрес вводить не нужно. Интерфейс на
[customtkinter](https://github.com/TomSchimansky/CustomTkinter) в тёмной теме, сеть на
стандартных сокетах Python.

Учебный проект ДВФУ, направление «Системное программирование».

## Как это выглядит

> Скриншотов пока нет. Их нужно снять на Windows и положить в папку `docs/`:
>
> - `docs/role.png` — окно выбора роли
> - `docs/server.png` — сервер ждёт соперника и показывает свой IP
> - `docs/game.png` — идёт игра
>
> После этого замените эту заметку строками вида `![Выбор роли](docs/role.png)`.

## Возможности

- Выбор роли при запуске: «Сервер» (создаёт игру) или «Клиент» (ищет игру).
- Автопоиск сервера в локальной сети через UDP broadcast.
- Запасной вариант: ввод IP-адреса сервера вручную.
- Поле 10×10, корабли: один на 4 клетки, два на 3, три на 2, четыре на 1.
- Случайная расстановка кораблей и кнопка «Расставить заново» до первого выстрела.
- Первым ходит сервер. Попал или потопил — ходишь ещё раз, промахнулся — ход переходит.
- Нельзя стрелять в одну клетку дважды и стрелять на чужом ходу.
- Индикатор соединения и сообщение «Соперник отключился» при обрыве связи.
- Кнопка «Играть снова» после окончания партии.
- Один файл `SeaBattle.exe` без картинок и других внешних файлов.

## Как это работает

```
  Ноутбук 1 (сервер)                         Ноутбук 2 (клиент)
  ──────────────────                         ──────────────────
  Выбор роли: «Сервер»                       Выбор роли: «Клиент»
          │                                          │
          │  UDP broadcast раз в секунду             │
          │  "sea-battle:5050" → порт 5051           │
          ├─────────────────────────────────────────►│ слушает порт 5051,
          │                                          │ берёт IP отправителя
          │                                          │
          │  TCP-подключение на порт 5050            │
          │◄─────────────────────────────────────────┤
          │  рассылка останавливается                │
          │                                          │
          │  shot 4 7                                │
          ├─────────────────────────────────────────►│ проверяет своё поле
          │                          result hit      │
          │◄─────────────────────────────────────────┤
          │  shot 5 7                                │
          ├─────────────────────────────────────────►│
          │                          result miss     │
          │◄─────────────────────────────────────────┤
          │                                          │ теперь ходит клиент
          │                                shot 0 0  │
          │◄─────────────────────────────────────────┤
          │  result miss                             │
          ├─────────────────────────────────────────►│
          │                   ...                    │
```

Каждый игрок хранит только своё поле. Получив выстрел, он проверяет его у себя и
отвечает результатом. Стрелявший помнит, куда стрелял, и отмечает результат на поле
соперника.

Сокеты читаются в отдельном потоке, который складывает строки в `queue.Queue`.
Окно раз в 50 мс забирает строки из очереди через `root.after`, поэтому виджеты
меняются только из главного потока.

## Протокол

Одна строка на сообщение, в конце `\n`. Координаты `X` (столбец) и `Y` (строка) — числа от 0 до 9.

| Сообщение     | Кто отправляет     | Что значит                                     |
|---------------|--------------------|------------------------------------------------|
| `shot X Y`    | тот, чей ход       | выстрел в клетку (X, Y)                        |
| `result miss` | получивший выстрел | промах, ход переходит к сопернику              |
| `result hit`  | получивший выстрел | попадание, стрелявший ходит снова              |
| `result sunk` | получивший выстрел | корабль потоплен, стрелявший ходит снова       |
| `result win`  | получивший выстрел | потоплен последний корабль, стрелявший победил |

Порты: `5050/TCP` — игра, `5051/UDP` — автопоиск.

## Запуск из исходников

Нужен Python 3.12 (с python.org, вместе с ним ставится tkinter).

```
git clone https://github.com/kkaraumi/kisik.git
cd kisik
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

Проверить игру можно и на одном ноутбуке: запустите `python main.py` в двух терминалах,
в одном окне выберите «Сервер», в другом «Клиент».

## Скачать готовый .exe

1. Откройте страницу [Releases](https://github.com/kkaraumi/kisik/releases).
2. Скачайте `SeaBattle.exe` из последней версии.
3. Запустите его на обоих ноутбуках. Python ставить не нужно.

## Сборка .exe

На Windows в папке проекта:

```
build.bat
```

Скрипт ставит зависимости и запускает

```
pyinstaller --onefile --windowed --name SeaBattle main.py
```

Готовый файл появится в `dist\SeaBattle.exe`.

Автоматическая сборка: при пуше тега вида `v1.0.0` GitHub Actions
(`.github/workflows/release.yml`) собирает `SeaBattle.exe` на Windows и прикрепляет его
к релизу.

```
git tag v1.0.0
git push origin v1.0.0
```

## Тесты

```
python -m unittest
```

Тесты проверяют логику `game.py`: случайная расстановка даёт 20 клеток кораблей без
наложений, выстрелы возвращают `miss` / `hit` / `sunk`, победа засчитывается после
потопления всех кораблей, повторный выстрел в ту же клетку ничего не меняет.

## Решение проблем

**Клиент пишет «Сервер не найден»**

- Оба ноутбука должны быть подключены к одной Wi-Fi сети.
- Университетский и другие общественные Wi-Fi часто блокируют связь между устройствами.
  Надёжнее раздать интернет с телефона (точка доступа) и подключить к ней оба ноутбука.
- Выключите VPN на обоих ноутбуках.
- Нажмите «Ввести IP вручную» и введите IP, который показан в окне сервера.

**Брандмауэр Windows**

При первом запуске Windows спрашивает, разрешить ли программе доступ к сети.
Поставьте галочку «Частные сети» и нажмите «Разрешить» на **обоих** ноутбуках:
серверу нужен входящий TCP на порт 5050, клиенту — входящий UDP на порт 5051.

Если окно не появилось или вы нажали «Отмена»:

1. Откройте «Брандмауэр Защитника Windows» → «Разрешение взаимодействия с приложением».
2. Найдите `SeaBattle` или `python` и отметьте «Частные».
3. Проверьте, что сеть Wi-Fi в Windows отмечена как «Частная», а не «Общедоступная».

**Подключение вручную не проходит**

С ноутбука-клиента проверьте, видит ли он сервер:

```
ping 192.168.0.10
Test-NetConnection 192.168.0.10 -Port 5050
```

- `ping` не проходит — ноутбуки в разных сетях или сеть блокирует связь между устройствами;
- `ping` проходит, но `TcpTestSucceeded : False` — брандмауэр на сервере блокирует игру.

**Windows не даёт запустить SeaBattle.exe**

Файл не подписан, поэтому SmartScreen может показать «Система Windows защитила ваш
компьютер». Нажмите «Подробнее» → «Выполнить в любом случае».

**«Порт 5050 занят»**

Сервер уже запущен в другом окне. Закройте его или подождите пару секунд и попробуйте снова.
